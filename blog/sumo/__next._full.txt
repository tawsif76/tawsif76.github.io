20:T3ca0,<p>For any researcher working in the VANET (Vehicular Ad-hoc Network) space, creating a realistic mobility simulation is the first crucial step. While network simulators like ns-3 are powerful, they don't inherently know how vehicles move in a real city. That’s where <strong>SUMO</strong> (Simulation of Urban MObility) comes in.</p>
<p>However, connecting SUMO with ns-3 can sometimes feel cumbersome. This guide provides a detailed, step-by-step workflow for taking real-world map data, creating a complex traffic scenario in SUMO, and finally, exporting that mobility information for use in your ns-3 simulation.</p>
<hr>
<h2>Step 1: Installation and Setup on Ubuntu</h2>
<p>First, let’s get the core tool installed. If you are running Debian or Ubuntu, SUMO is available in the regular repositories, but for research purposes, you generally want the latest stable version.</p>
<h3>Recommended Installation via PPA</h3>
<p>Use the official SUMO PPA (Personal Package Archive) to ensure you aren't using outdated binaries.</p>
<pre><code class="hljs language-bash"><span class="hljs-built_in">sudo</span> add-apt-repository ppa:sumo/stable
<span class="hljs-built_in">sudo</span> apt-get update
<span class="hljs-built_in">sudo</span> apt-get install sumo sumo-tools sumo-doc
</code></pre>
<h3>Verifying the Installation</h3>
<p>On Ubuntu, these binaries are installed in <code>/usr/bin</code>, which is already in your system path. To confirm that SUMO is correctly set up and that your environment variables are ready, run:</p>
<pre><code class="hljs language-bash"><span class="hljs-built_in">echo</span> <span class="hljs-variable">$SUMO_HOME</span>
</code></pre>
<p>If the output is <code>/usr/share/sumo</code>, you are good to go.</p>
<hr>
<h2>Step 2: Getting Real-World Map Data</h2>
<p>We need a realistic road network. The best source for this is <strong>OpenStreetMap (OSM)</strong>.</p>
<ol>
<li>Go to the <a href="https://www.openstreetmap.org">OSM website</a> and search for your area of interest.</li>
<li>Zoom in to select a specific portion (simulating an entire country is usually unnecessary and computationally heavy).</li>
<li>Click the <strong>Export</strong> button to download the map as <code>map.osm</code>.</li>
</ol>
<p><img src="/images/blog/osm.webp" alt="OpenStreetMap Export Button"></p>
<blockquote>
<p><strong>Note:</strong> If you are trying to download a very large area, the standard export button might fail. In that case, you will need to download planet dumps from <a href="https://planet.openstreetmap.org/">planet.openstreetmap.org</a>.</p>
</blockquote>
<hr>
<h2>Step 3: Converting the Map for SUMO</h2>
<p>You now have a raw map file (<code>.osm</code>), but SUMO cannot read it directly. We need to convert it into a <code>.net.xml</code> file using the <code>netconvert</code> tool.</p>
<p>We will use several flags to clean up the map and make it suitable for vehicle simulation:</p>
<ul>
<li><strong><code>--remove-edges.by-vclass</code></strong>: SUMO provides many vehicle classes (<a href="https://sumo.dlr.de/docs/Definition_of_Vehicles%2C_Vehicle_Types%2C_and_Routes.html">vClass</a>). Using this, we can remove roads that belong to certain vehicle classes and keep only the ones needed.</li>
<li><code>--tls.guess-signals</code>: Automatically detects where traffic lights should be.</li>
<li><code>--tls.default-type actuated</code>: Sets traffic lights to be adaptive rather than fixed-time.</li>
<li><code>--junctions.join</code>: Merges complicated, messy intersections into single, clean junctions.</li>
</ul>
<p>Run the following command:</p>
<pre><code class="hljs language-bash">netconvert --osm-files map.osm \
           --output-file map.net.xml \
           --remove-edges.by-vclass bicycle,pedestrian,rail,truck \
           --tls.guess-signals \
           --tls.default-type actuated \
           --junctions.join
</code></pre>
<hr>
<h2>Step 4: Generating Traffic</h2>
<p>An empty road network needs vehicles. We can use the <a href="https://sumo.dlr.de/docs/Tools/Trip.html"><code>randomTrips</code></a> included with SUMO to generate random traffic. The <code>randomTrips.py</code> script is already available in your SUMO installation under: <code>/usr/share/sumo/tools</code>.</p>
<p>In random trip, a "trip" consists of a vehicle starting at an origin edge and driving to a destination edge at a specific time. To make this realistic, we need to apply a few specific settings:</p>
<ol>
<li><strong>Fringe Factor (<code>--fringe-factor &#x3C;value></code>)</strong>: By default, random trips may start from the center of the map, which can look unrealistic. The fringe factor increases the likelihood that vehicles start or end at the edges of the map. Higher values make border edges more likely to be chosen.</li>
<li><strong>Period (<code>--period &#x3C;value></code>)</strong>: Controls traffic density by specifying how frequently vehicles are inserted into the network. SUMO will generate approximately <strong>one vehicle every <code>&#x3C;value></code> seconds</strong>.</li>
<li><strong>Validation (<code>--validate</code>)</strong>: This ensures that the script doesn't create routes that are mathematically impossible to drive (e.g., disconnected roads).</li>
<li><strong>End Time (<code>-e &#x3C;value></code> or <code>--end &#x3C;value></code>)</strong>: The <strong>end time</strong> defines how long the trip-generation process should run.</li>
</ol>
<p>Run the traffic generation script:</p>
<pre><code class="hljs language-bash">python3 <span class="hljs-variable">$SUMO_HOME</span>/tools/randomTrips.py \
        -n map.net.xml \
        -o trips.rou.xml \
        -e 500 \
        --period 2 \
        --fringe-factor 5 \
        --seed 42 \
        --validate
</code></pre>
<hr>
<h2>Step 5: The Configuration File</h2>
<p>A <code>.sumocfg</code> file is the main configuration file for SUMO. Whenever you start a SUMO simulation, it needs to know:</p>
<ul>
<li>Which map to load</li>
<li>Which vehicles/trips to load</li>
<li>Which additional objects (vehicle types, detectors, bus stops, etc.)</li>
<li>What time period to simulate</li>
</ul>
<p>Instead of typing all these as long command-line arguments every time, SUMO reads everything from one single <code>.sumocfg</code> file. In simple words, <code>.sumocfg</code> is the master file that organizes the entire SUMO simulation.</p>
<h3>1. Define Vehicle Types (<code>vtypes.add.xml</code>)</h3>
<p>First, create a small file to define the physics of your cars (acceleration, size, color).</p>
<pre><code class="hljs language-xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">additional</span>></span>
    <span class="hljs-tag">&#x3C;<span class="hljs-name">vType</span> <span class="hljs-attr">id</span>=<span class="hljs-string">"car"</span> <span class="hljs-attr">length</span>=<span class="hljs-string">"5.0"</span> <span class="hljs-attr">maxSpeed</span>=<span class="hljs-string">"40.0"</span> <span class="hljs-attr">accel</span>=<span class="hljs-string">"2.6"</span> <span class="hljs-attr">decel</span>=<span class="hljs-string">"4.5"</span> <span class="hljs-attr">tau</span>=<span class="hljs-string">"1.2"</span>
           <span class="hljs-attr">vClass</span>=<span class="hljs-string">"passenger"</span> <span class="hljs-attr">color</span>=<span class="hljs-string">"255,255,255"</span>/></span>
<span class="hljs-tag">&#x3C;/<span class="hljs-name">additional</span>></span>
</code></pre>
<h3>2. Create the Master Config (<code>map.sumocfg</code>)</h3>
<p>Create this file to tie everything together:</p>
<pre><code class="hljs language-xml"><span class="hljs-tag">&#x3C;<span class="hljs-name">configuration</span>></span>
    <span class="hljs-tag">&#x3C;<span class="hljs-name">input</span>></span>
        <span class="hljs-tag">&#x3C;<span class="hljs-name">net-file</span> <span class="hljs-attr">value</span>=<span class="hljs-string">"map.net.xml"</span>/></span>
        <span class="hljs-tag">&#x3C;<span class="hljs-name">route-files</span> <span class="hljs-attr">value</span>=<span class="hljs-string">"routes.rou.xml"</span>/></span>
        <span class="hljs-tag">&#x3C;<span class="hljs-name">additional-files</span> <span class="hljs-attr">value</span>=<span class="hljs-string">"vtypes.add.xml"</span>/></span>
    <span class="hljs-tag">&#x3C;/<span class="hljs-name">input</span>></span>
    <span class="hljs-tag">&#x3C;<span class="hljs-name">time</span>></span>
        <span class="hljs-tag">&#x3C;<span class="hljs-name">begin</span> <span class="hljs-attr">value</span>=<span class="hljs-string">"0"</span>/></span>
        <span class="hljs-tag">&#x3C;<span class="hljs-name">end</span> <span class="hljs-attr">value</span>=<span class="hljs-string">"1000"</span>/></span>
    <span class="hljs-tag">&#x3C;/<span class="hljs-name">time</span>></span>
<span class="hljs-tag">&#x3C;/<span class="hljs-name">configuration</span>></span>
</code></pre>
<p>You can now verify your work by running the visual simulation:</p>
<pre><code class="hljs language-bash">sumo-gui -c map.sumocfg
</code></pre>
<p><strong>💡 Tip:</strong> In the GUI, look for the "Real World" option in the visualization drop-down menu. It makes the map look realistic. You can also adjust the <strong>delay slider</strong> to slow down or speed up the visualization.</p>
<p><img src="/images/blog/sumo.webp" alt="SUMO GUI"></p>
<h3>⚠️ Teleport Warnings</h3>
<p>You may see warnings in the log such as:
<code>Warning: Teleporting vehicle 'veh123' (jammed for too long)</code></p>
<p>A teleport means a vehicle was stuck and SUMO moved it forward artificially. Fewer teleports generally indicate a cleaner and more realistic simulation. Too many vehicles or disconnected edges can increase teleporting.</p>
<hr>
<h2>Step 6: Exporting Traces to ns-3</h2>
<p>Now for the most important part: getting this data into ns-3. We need to convert the SUMO movement into a format ns-3 understands, typically the <strong>ns-2 mobility trace format</strong>.</p>
<p>This is a two-step process.</p>
<h3>1. Generate FCD (Floating Car Data) Output</h3>
<p>Run SUMO in command-line mode to output raw position data.</p>
<pre><code class="hljs language-bash">sumo -c map.sumocfg --fcd-output sumoTrace.xml
</code></pre>
<h3>2. Convert to ns-2 format</h3>
<p>Use the trace exporter tool to convert the XML into a TCL script.</p>
<pre><code class="hljs language-bash">python3 <span class="hljs-variable">$SUMO_HOME</span>/tools/traceExporter.py --fcd-input sumoTrace.xml --ns2mobility-output ns2mobility.tcl
</code></pre>
<p>You now have <code>ns2mobility.tcl</code>. If you open it, you will see lines like <code>$node_(0) setdest ...</code>. These are instructions telling ns-3 exactly where node "X" should be at any given second.</p>
<hr>
<h2>Step 7: Integrating with ns-3</h2>
<p>Finally, we need to tell your ns-3 simulation to use this trace file. You will use the <code>Ns2MobilityHelper</code> class.</p>
<p>Here is a clean example of how to set this up in your main script:</p>
<pre><code class="hljs language-cpp"><span class="hljs-meta">#<span class="hljs-keyword">include</span> <span class="hljs-string">"ns3/core-module.h"</span></span>
<span class="hljs-meta">#<span class="hljs-keyword">include</span> <span class="hljs-string">"ns3/mobility-module.h"</span></span>
<span class="hljs-meta">#<span class="hljs-keyword">include</span> <span class="hljs-string">"ns3/ns2-mobility-helper.h"</span></span>
<span class="hljs-meta">#<span class="hljs-keyword">include</span> <span class="hljs-string">"ns3/node-container.h"</span></span>

<span class="hljs-keyword">using</span> <span class="hljs-keyword">namespace</span> ns3;

<span class="hljs-function"><span class="hljs-type">int</span> <span class="hljs-title">main</span> <span class="hljs-params">(<span class="hljs-type">int</span> argc, <span class="hljs-type">char</span> *argv[])</span>
</span>{
    <span class="hljs-comment">// This must match the number of vehicles generated in your trace</span>
    <span class="hljs-type">uint32_t</span> node_count = <span class="hljs-number">150</span>;
    <span class="hljs-type">double</span> sim_time = <span class="hljs-number">1200.0</span>;

    NodeContainer nodes;
    nodes.<span class="hljs-built_in">Create</span> (node_count);

    <span class="hljs-comment">// Path is relative to the ns-3 root directory</span>
    <span class="hljs-function">Ns2MobilityHelper <span class="hljs-title">ns2</span><span class="hljs-params">(<span class="hljs-string">"path/to/your/ns2mobility.tcl"</span>)</span></span>;
    ns<span class="hljs-number">2.</span><span class="hljs-built_in">Install</span>(nodes);

    <span class="hljs-comment">// ... Install network stack, devices, and applications here ...</span>

    Simulator::<span class="hljs-built_in">Stop</span>(<span class="hljs-built_in">Seconds</span>(sim_time));
    Simulator::<span class="hljs-built_in">Run</span>();
    Simulator::<span class="hljs-built_in">Destroy</span>();
    <span class="hljs-keyword">return</span> <span class="hljs-number">0</span>;
}
</code></pre>
<h3>⚠️ Warning: Application Start and End Times</h3>
<p>There is one critical detail that we should be aware of. In SUMO, vehicles enter the simulation at different times. In ns-3, the nodes technically exist from time <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>t</mi><mo>=</mo><mn>0</mn></mrow><annotation encoding="application/x-tex">t=0</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.6151em;"></span><span class="mord mathnormal">t</span><span class="mspace" style="margin-right:0.2778em;"></span><span class="mrel">=</span><span class="mspace" style="margin-right:0.2778em;"></span></span><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">0</span></span></span></span>, but they might sit at a default coordinate (like 0,0,0) until the trace file tells them to move.</p>
<p><strong>If you start your network application (like a broadcast) on all nodes at <span class="katex"><span class="katex-mathml"><math xmlns="http://www.w3.org/1998/Math/MathML"><semantics><mrow><mi>t</mi><mo>=</mo><mn>0</mn></mrow><annotation encoding="application/x-tex">t=0</annotation></semantics></math></span><span class="katex-html" aria-hidden="true"><span class="base"><span class="strut" style="height:0.6151em;"></span><span class="mord mathnormal">t</span><span class="mspace" style="margin-right:0.2778em;"></span><span class="mrel">=</span><span class="mspace" style="margin-right:0.2778em;"></span></span><span class="base"><span class="strut" style="height:0.6444em;"></span><span class="mord">0</span></span></span></span>, you will experience massive packet loss.</strong></p>
<p><strong>🔧 The Fix:</strong> Start and end the the custom vehicle application at the time it actually enters in the sumo simulation. Check my GitHub <a href="https://github.com/tawsif76/vanet-beacon/tree/master">repo</a> to learn more about it in detail.</p>
